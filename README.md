# Questão 1: (Comentário sobre: O software é intangivel)
  Software é considerado intangível porque não é algo físico, como um carro ou um prédio. Ele não pode ser tocado, apenas executado ou utilizado. Mesmo assim, ele é real, pois resolve problemas e realiza tarefas no mundo real. Diferente de outras engenharias, onde o resultado é visível e concreto, o software existe de forma lógica e digital. Isso torna mais difícil medir sua qualidade e evolução, exigindo métodos mais rigorosos para garantir que funcione corretamente.

# Questão 2: (Engenharia de Software = Programação + tempo, escalabilidade e trade-offs)

  Engenharia de software vai além de apenas programar. Não se trata só de escrever código, mas de pensar em como esse código vai funcionar ao longo do tempo, crescer e se adaptar. Um software precisa ser sustentável, ou seja, fácil de manter e evoluir.
  Além disso, é necessário considerar a escalabilidade (suportar mais usuários ou dados) e os trade-offs, que são decisões onde se ganha em um aspecto e perde em outro. Por exemplo, melhorar desempenho pode aumentar o custo. Portanto, engenharia de software envolve planejamento, organização e decisões estratégicas, não apenas programação.

# Questão 3: (Requisitos não funcionais)

1. Escalabilidade
Capacidade do sistema de suportar aumento de usuários ou carga sem perder desempenho.

2. Segurança
Capacidade de proteger dados e evitar acessos não autorizados.

3. Usabilidade
Facilidade de uso do sistema, garantindo que o usuário consiga utilizá-lo sem dificuldade.

4. Desempenho
Velocidade de resposta e eficiência do sistema ao executar tarefas.

5. Confiabilidade (ou robustez)
Capacidade do sistema de funcionar corretamente mesmo diante de erros ou situações inesperadas.

# Questão 4: (Trade-offs)

1. Segurança vs Usabilidade
Exemplo: autenticação em dois fatores.
Aumenta a segurança, mas deixa o acesso mais lento e menos prático para o usuário.

2. Desempenho vs Custo
Exemplo: usar servidores mais potentes.
Melhora a velocidade do sistema, mas aumenta o custo da infraestrutura.

3. Escalabilidade vs Complexidade
Exemplo: usar arquitetura de microserviços.
Permite crescer melhor, mas deixa o sistema mais complexo de desenvolver e manter.
